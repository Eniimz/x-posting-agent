I've been working on some pretty fun engineering problems lately, and I've realized I enjoy performance engineering a lot more than I expected. Over the past few weeks I reworked a big part of a asset pipeline to make uploads significantly faster without changing any user-facing features.

Some of the things I worked on:
1. Added content-based deduplication using SHA-256 hashes so identical assets are detected before upload and duplicate uploads are skipped entirely
2. Parallelized storage uploads and database writes to reduce overall upload latency
3. Implemented optimistic uploads so assets appear instantly while processing and uploads continue in the background
4. Moved thumbnail generation and asset registration off the critical path into background jobs
5. Added cleanup logic for partial failures to keep storage and database state consistent
6. Switched to content-addressed asset keys to eliminate unnecessary uploads and reduce storage overhead

The more I work on systems like this, the more I appreciate the engineering that users never notice until it's missing.

[7 tips Anthropic Engineers use to Prompt Claude]

1/ delete before you write

anthropic runs different system prompts per model now. frontier models get the lean prompt: the full 80% cut. older models keep the original.

what they removed: examples, because the model outperforms them. and "do not do this" rules, because hard constraints confuse the model when they collide with user instructions later.

their test for every line: is this 100% true? an instruction that's 90% right ships 100% of the time the other 10% becomes confusion. soften it until it's always true, or delete it.

2/ rebuild the loop for multiday runs

single turns run for minutes. autonomous runs stretch to days. official recommendation: check on runs through scheduled jobs, not blocking calls.

supervision becomes cron, not await.

3/ hide the token counter

show fable a remaining-context countdown and it starts suggesting new sessions and trimming its own work.

keep operator dashboards out of model context. observability is for you, not the model.

4/ make it prove progress

instruct the model to verify every progress claim against an actual tool result before reporting it. anthropic says this nearly eliminated fabricated status updates in their testing even on tasks designed to bait them.

5/ build a verbatim channel

tool inputs are never summarized. a simple client-side display tool becomes word-for-word delivery from a mid-run agent. catch: define the tool and the model rarely calls it. you need elicitation language in the system prompt too.

6/ audit for the reasoning landmine

old skills that say "explain your reasoning in your response" can now trigger the reasoning_extraction refusal. with fallback configured, those requests quietly route to opus 4.8.

find these instructions before production does.

7/ route by effort, not by model

low effort on fable 5 often beats xhigh on the previous generation. the routing decision moved from "which model" to "which effort level."

and prompts fork by model tier too: lean for frontier, full for older. one prompt for all models is over.
